# Geda Transfer — desktop

The macOS and Windows app. A window over `core/`, and nothing more
(AGENTS.md §2): the receiver it runs is `core/service`, the same one `gedad`
runs on a NAS.

## What is here

```
main.go, tray.go        The Wails shell: window, tray, folder picker, autostart.
internal/app/           Everything the window can ask for. Imports no UI package.
internal/settings/      The user's preferences, stored in the ledger.
internal/autostart/     Per-user login item: LaunchAgent, Run key, XDG.
internal/qrsvg/         The pairing code, drawn as SVG.
internal/reveal/        "Show in Finder", per platform.
internal/icons/         Tray artwork, generated by gen.go and committed.
internal/gate/          Drives the app headlessly for scripts/verify-p6.sh.
frontend/               The page: strict TypeScript, no framework.
```

`internal/app` deliberately does not import Wails. Every method the window
calls can be called from a test with no toolkit, which is what makes the phase
gate something a script can drive.

## Building

```
cd frontend && npm ci && npm run build   # the page is embedded, so it must exist first
cd .. && wails build
```

`wails dev` runs it with a live-reloading page, and also serves the app at
<http://localhost:34115> so the bound Go methods can be driven from a browser.

`go build ./...` alone will fail until the page has been built once: the binary
embeds `frontend/dist`, which is generated and not checked in.

`wails dev` already keeps its own state: it compiles with the `dev` build tag,
which puts the ledger in `geda-dev`, qualifies the single-instance lock, and
titles the window "(dev)". A development run therefore cannot pair a phone into
— or damage the identity of — the app you actually use.

To point a run somewhere else again:

```
GEDA_STATE_DIR=/tmp/geda-test wails dev
```

`GEDA_STATE_DIR` is used exactly as given, with no `-dev` suffix.

## State

The ledger and the TLS identity live in the user's config directory —
`~/Library/Application Support/geda` on macOS, `%AppData%\geda` on Windows.

**Losing that directory makes every paired phone fail with a pin mismatch, and
there is no override** (AGENTS.md §3.5). It is deliberately outside the app
bundle so that updates and reinstalls do not touch it.

There is no configuration file. Settings live in the ledger, because a second
file that the window and a text editor could both write would only create a
question about which of them wins (docs/DECISIONS.md).

## Icons

`internal/icons/gen.go` draws the app icon, the macOS template icon, and the
Windows `.ico` from one description, so the three cannot drift apart:

```
go run ./internal/icons/gen.go
```

The output is committed. A build must not need this to have been run.

## Testing

```
go test ./...                       # the live view, the settings, the pairing code
go test -tags dev ./internal/settings/   # a dev build keeps its own state
cd frontend && npm run typecheck
cd frontend && npm test             # what the window shows a person
../scripts/verify-p6.sh             # the phase gate, from the repository root
```

The window's tests run the real view code in jsdom against a stubbed bridge.
They cover what the Go gate cannot: that a first-time user is told what to do
next, that "already had it" is not reported as "stored", and that a filename
which came off a phone is rendered as text and never as markup.
